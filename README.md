# Курсов проект по Операционни системи: Контейнеризация на Flask и MySQL

Този проект демонстрира контейнеризация на многокомпонентно уеб приложение и конфигуриране на изолирана мрежова свързаност между компонентите с помощта на **Docker** и **Docker Compose**.

---

## 1. Структура на проекта
- **`backend/`** — съдържа сорс кода на Python приложението (`app.py`), списъка със зависимости (`requirements.txt`) и неговия `Dockerfile`.
- **`compose.yml`** — конфигурационният файл, който оркестрира и стартира двете услуги едновременно.
- **`README.md`** — документация на проекта (този файл).

---

## 2. Описание на компонентите
1. **web-app (Бекенд услуга)**: Микро уеб сървър, написан на Python с микро-фреймуърка **Flask**. При стартиране прави автоматични опити за връзка с базата данни през определен интервал от време (с вграден механизъм за изчакване). При успешен тест визуализира съобщение в браузъра на порт `5000`.
2. **database-service (База данни)**: Използва официален Docker образ на **MySQL (версия 8.0)**. При първоначално стартиране автоматично създава база данни с име `os_db` и конфигурира нужните потребителски права и пароли.

---

## 3. Мрежова комуникация (Networking)
Контейнерите комуникират в собствена, изолирана от външния свят виртуална мрежа (Bridge Network), създадена автоматично от Docker Compose. 

В сорс кода на Python (`app.py`), вместо твърдо зададени IP адреси или локален `localhost`, за адрес на хоста е използвано DNS името на самата услуга — **`db`**. Docker вграденият DNS сървър автоматично превежда това име до правилния вътрешен IP адрес на MySQL контейнера, осигурявайки сигурна изолирана връзка.

---

## 4. Постоянен обем от данни (Data Persistence)
За да се предотврати загуба на информация при спиране или премахване на контейнерите, в `compose.yml` е конфигуриран споделен обем от данни — **Docker Volume** с име `db_data`. Той подсигурява, че директорията `/var/lib/mysql` вътре в контейнера е свързана със защитено пространство на хост машината.
